# GhidraDwarfForge 0.1.0-alpha.2

This corrective prerelease fixes six correctness findings in alpha.1 and
strengthens ELF layout, large-file and cancellation handling. Upgrade the
extension and regenerate affected sidecars; existing `.dbg` files are not
repaired automatically. The original target remains unchanged during export.
The alpha.1 tag and release assets remain available without modification.

GhidraDwarfForge exports the current analyzed Ghidra program as a DWARF 5
sidecar and deterministic synthetic C source. Default outputs are
`<binary>.dbg` and `<binary>.dbg.c`, beside the original ELF. The generated C
is decompiler output, not recovered original source.

## Correctness fixes

1. Headless log paths are checked before opening or truncating the log. Paths
   that alias inputs, outputs, native libraries or project data are rejected,
   including symbolic and hard links. PowerShell resolves paths against its
   current filesystem location, treats wildcard characters literally, and
   rejects Windows alternate data streams for explicit logs. Existing-project
   exports with an explicit log require the original input path so this
   preflight can protect it; omit the log option to use private capture.
2. Exported addresses reverse Ghidra's recorded ELF import mapping correctly,
   including nonzero load-segment file offsets, explicit rebases, and load
   headers late in an extended program table.
3. Bit-field members emit `DW_AT_data_bit_offset` without a conflicting
   `DW_AT_data_member_location`, so GDB reads the intended bits.
4. Inherited `.gdb_index` is retired when Forge replaces the debug view.
   Stale compiler DWARF, compressed sections, `.gnu_debuglink`,
   `.gnu_debugaltlink`, and `.gnu_debugdata` are also retired inside the
   sidecar. The original ELF and its debug metadata remain unchanged.
5. Big-endian bit-field offsets use the actual component storage width,
   independently of the base integer type. Value-based compiler-oracle/GDB
   tests cover four-byte integer bit fields stored in a one-byte component.
6. The line table records the absolute output directory so GDB can find the
   generated source from an unrelated working directory, including paths with
   spaces. Moving the artifacts still requires a GDB `directory` or
   `set substitute-path` rule. Reruns are deterministic at the same destination;
   changing the destination changes the recorded source directory.

## ELF robustness and cancellation

- Extended section counts and section-name indexes use the ELF escape fields
  independently. Original section indexes are preserved.
- Section tables without names and inputs without any section-header table
  are accepted. Existing unnamed sections retain empty names; names are not
  guessed from their contents.
- Extended program-header counts (`PN_XNUM`) are decoded through section zero.
  Build-ID notes remain visible even when only late program headers describe
  them; partially covered note segments do not duplicate the identity.
- Original file bytes are copied with bounded I/O instead of one Java array.
  A source-built input larger than 2 GiB passes the production Ghidra export,
  structural validators, GDB checks and deterministic reruns. Import-mode
  wrappers select Ghidra's ELF loader explicitly to avoid unrelated format
  probes on large files.
- Cancellation is checked between bounded copy/write operations and before
  final replacement. A real mid-copy cancellation reports `CANCELLED`, leaves
  the original and both previous artifacts intact, and removes staging files.

## Install and use

Download `GhidraDwarfForge-0.1.0-alpha.2-ghidra-12.0.3.zip` and verify it
against the release's `SHA256SUMS`. Close Ghidra before upgrading. Keep a copy
of any locally modified extension files, move the old `GhidraDwarfForge`
directory out of `<ghidra>/Ghidra/Extensions`, and extract the new ZIP there.
Use a clean replacement directory so files from different releases are not
mixed. The resulting path must be
`<ghidra>/Ghidra/Extensions/GhidraDwarfForge`; then restart Ghidra.

Ghidra 12.0.3 and a Java 21-compatible runtime are required. The bundle includes
Linux x86-64 and Windows x86-64 native libraries, provenance/checksums,
third-party notices, and the exact corresponding patched libdwarf 2.3.2
source. No separate libdwarf installation is needed. The generated
`extension.properties` version is the Ghidra compatibility version (`12.0.3`);
the extension's own version is in `VERSION` and `RELEASE-MANIFEST.txt`.

See the [installation and headless usage guide](https://github.com/zwilcox/GhidraDwarfForge/blob/v0.1.0-alpha.2/docs/RELEASE.md) for Bash and
PowerShell commands. Load the result explicitly in GDB with:

```gdb
file /path/to/program.elf
set auto-solib-add off
symbol-file /path/to/program.elf.dbg
```

## Validation and support scope

The corrective implementation baseline `3e47589` passed all twelve jobs in
[hosted run 40047390539](https://github.com/zwilcox/GhidraDwarfForge/actions/runs/40047390539).
This includes native/ABI tests, the extension build, reproducible bundle
assembly, five target lanes, Windows-hosted export, and the aggregate
`required-validation` gate. Exact versioned commit/package validation remains
required before publication; its commit and CI run must accompany the GitHub
release. See the [validation record](https://github.com/zwilcox/GhidraDwarfForge/blob/v0.1.0-alpha.2/docs/VALIDATION.md) for the implementation
tests and their precise boundaries.

| Scope | Validated profile |
|---|---|
| Ghidra hosts | Linux x86-64 on Ubuntu 24.04; Windows x86-64 |
| ELF targets | x86-64; AArch64; ARM32 ARMv7 hard-float, little-endian ARM state; MIPS32 big-endian and little-endian |
| Target roles | Non-PIE executables, PIE, shared objects, stripped/partially stripped inputs, and section-header-free executables in the documented fixture matrix |
| Runtime behavior | Native Linux or QEMU with GDB; Windows-hosted artifacts receive structural checks and comparison with the Linux reference |

GNU readelf, LLVM and libdwarf validators check generated artifacts in the
Linux lanes. Windows uses readelf and LLVM; standalone `dwarfdump` is not
available in that runner. These are tested profiles, not a promise that every
binary or ABI for those processors works. Broader real-world coverage remains;
the new uncurated GNU `true` and `basename` tests are two examples, not an
exhaustive application corpus.

## Limits and remaining work

- Native Linux and QEMU 8.2.2 cannot directly execute the tested `PN_XNUM`
  input. Import/export and static GDB use that exact extended input. Runtime
  tests use its ordinary load-image counterpart only after proving unchanged
  load bytes and addresses. Extended-input execution is not claimed.
- ELF metadata is bounded: at most 262,144 headers per program or section
  table, 64 MiB per raw table, 16 MiB each for section-name bytes and aggregate
  decoded names, and 65,536 bytes per individual name excluding NUL. File
  offsets/sizes use nonnegative signed 64-bit values. ELF32 output fields must
  fit unsigned 32 bits and the file end must not exceed 4 GiB. Generated DWARF
  and Ghidra extraction models still reside in memory. These are implementation
  bounds, not constant-memory decompilation; see [ADR 0001](https://github.com/zwilcox/GhidraDwarfForge/blob/v0.1.0-alpha.2/docs/ADR-0001-ELF-SIDECAR.md).
- Imported functions and thunks are diagnosed and omitted. Distinct linkage
  names, richer function/class/lexical scopes, entry points that are not the
  lowest function-body address, and broader variable-lifetime/storage cases
  remain incomplete. This candidate excludes later feature-branch work.
- Variable locations are conservative and can be unavailable when Ghidra
  cannot justify them. The exporter generates no synthetic unwind information.
- Wrapper exit code zero includes `PARTIAL` exports. Inspect the JSON report
  for omitted information and diagnostics.
- Automatic installation into build-ID directories and optional
  `.gnu_debuglink` attachment are not provided. Matching build-ID discovery
  works when the sidecar is installed into the standard layout separately.
- Automated Linux GUI fallback is tested; manual Script Manager launch and
  Windows chooser/cancellation journeys remain unverified.
- Older Linux distributions, PE/PDB, Mach-O/dSYM, macOS hosts, Windows on ARM,
  x86-32, Thumb, big-endian ARM and other unvalidated profiles are outside this
  release's support scope.
